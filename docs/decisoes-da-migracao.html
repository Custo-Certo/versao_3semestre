Arquitetura

Como o sistema está organizado

O Prof. Furgeri pede duas coisas que se resolvem no mesmo desenho: sistema em camadas e manipulação de banco com acesso via rede local. O diagrama mostra as duas — a pilha de camadas à esquerda e a conexão que sai da máquina pela porta 3306.

Por que a separação importa na prática: trocar o banco de MySQL para outro exigiria reescrever apenas o pacote dao — quatro classes. A tela, as regras de autenticação e o modelo de dados não têm uma linha sequer que saiba qual banco está embaixo.

Como converter os tipos de SQLite para MySQL?

Não é conversão automática. O SQLite é frouxo com tipos e o MySQL não é — e uma escolha errada aqui vira erro de centavo no CMV, que é justamente o que o sistema existe para calcular.

A
Caminho sugerido DECIMAL para dinheiro, DATE/DATETIME para datas, ENUM para os domínios fechados preco e preco_unitario viram DECIMAL(10,2) em vez de REAL — ponto flutuante em dinheiro acumula erro. As datas em TEXT viram DATE e DATETIME com DEFAULT CURRENT_TIMESTAMP. Os CHECK (... IN ...) de unidade e tipo viram ENUM. Quantidades ficam DECIMAL(10,3) por causa das gramas.
Também decidir: InnoDB + utf8mb4Também decidir: nomes em snake_case mantidos

Banco de dados

O modelo das tabelas de acesso

O Prof. Marlon pede modelagem por DER, criação em MySQL, restrições de chave primária e estrangeira, e no mínimo 5 linhas por tabela. Estas duas tabelas cumprem os quatro itens — e são o primeiro pedaço do sistema a sair do SQLite.

usuarios Contas de acesso, uma por pessoa que usa o sistema.
idINT PKNOT NULL Chave primária com AUTO_INCREMENT. É o que log_acesso referencia.
nomeVARCHAR(120) NOT NULLCHECK Nome completo. O CHECK exige ao menos 3 caracteres depois de remover espaços, o que barra nome vazio ou só com espaço.
emailVARCHAR(120) UNIQUENOT NULLCHECK É o login. O UNIQUE impede duas contas com o mesmo e-mail; o CHECK exige o formato mínimo algo@algo.algo.
senha_hashVARCHAR(255) NOT NULL Resultado do PBKDF2 em Base64. Nunca a senha legível.
saltVARCHAR(64) NOT NULL Valor aleatório de 16 bytes, diferente para cada conta. É o que faz duas pessoas com a mesma senha terem hashes diferentes.
perfilENUM NOT NULLDEFAULT 'OPERADOR' Aceita apenas ADMINISTRADOR, GESTOR ou OPERADOR. O banco recusa qualquer outro valor — a regra não depende da aplicação lembrar dela.
ativoBOOLEAN NOT NULLDEFAULT TRUE Conta desligada não entra, mas continua no banco e mantém o histórico. É como se inativa um funcionário que saiu.
criado_emDATETIME NOT NULLDEFAULT CURRENT_TIMESTAMP Preenchido pelo banco, não pela aplicação.
ultimo_acessoDATETIME NULL Atualizado a cada login aceito. Nulo enquanto a pessoa nunca entrou — e a tela sabe dizer "este é o seu primeiro acesso".
log_acesso Uma linha por tentativa de login, aceita ou recusada.
idINT PKNOT NULL Chave primária com AUTO_INCREMENT.
usuario_idINT FKNULL Aponta para usuarios.id. Fica nulo quando o e-mail digitado não corresponde a nenhuma conta.
email_digitadoVARCHAR(120) NOT NULL O que foi realmente digitado. Guardar isto é o que permite descobrir tentativas contra e-mails inexistentes.
sucessoBOOLEAN NOT NULL Se as credenciais foram aceitas.
origemVARCHAR(120) NULL Nome e IP da máquina de onde partiu a tentativa. Numa rede local com várias máquinas, é o que identifica de qual delas veio.
data_horaDATETIME NOT NULLDEFAULT CURRENT_TIMESTAMP Momento da tentativa, carimbado pelo banco.

São seis restrições nomeadas: duas chaves primárias, uma chave estrangeira, uma unicidade e dois CHECK. Somam-se a elas o ENUM do perfil, os NOT NULL e os DEFAULT, que o MySQL guarda como propriedade das colunas e não como restrição nomeada. Tudo em InnoDB, o único motor do MySQL que faz valer chave estrangeira.

Modelo completo

As quatro tabelas do sistema em MySQL

O banco deixou de ser só a autenticação. As tabelas de estoque saíram do SQLite e foram convertidas seguindo o caminho D6-A: dinheiro em DECIMAL, datas em DATE e domínios fechados em ENUM.

Coluna no SQLiteVirou no MySQLPor quê
preco REAL DECIMAL(10,2) Ponto flutuante acumula erro de centavo. Num sistema que existe para apurar custo, esse erro apareceria direto no CMV.
qtd REAL DECIMAL(10,3) Três casas decimais dão precisão de grama, que é o que a balança lê.
validade TEXT DATE Data como texto não permite comparar nem ordenar de forma confiável. Com DATE, o alerta de vencimento vira uma consulta simples.
criado_em TEXT DATETIME DEFAULT CURRENT_TIMESTAMP O banco carimba a hora sozinho, e a aplicação não pode errar isso.
CHECK (unidade IN ...) ENUM('kg','g','L','ml','un') O domínio fechado fica declarado no tipo da coluna, e o MySQL recusa qualquer valor fora da lista.
CHECK (tipo IN ...) ENUM('entrada','saida') Mesma ideia, aplicada à natureza da movimentação.

Tempo real

A balança, e onde estava a demora

O desktop passou a receber o peso ao vivo, pelo mesmo fluxo que o painel web já consumia. Ao investigar a latência, o gargalo apareceu num lugar diferente do esperado: não era a rede, era o firmware.

OndeO que mudouEfeito na latência
firmware/src/main.cpp get_units(5) virou is_ready() + get_units(1) com média móvel −400 ms por ciclo
firmware/src/main.cpp HTTPClient estático com setReuse(true) −1 handshake por envio
firmware/src/main.cpp Consulta de tara removida; passa a ler a resposta do POST −1 chamada bloqueante por segundo
balancaController.ts POST /balanca/peso devolve tarar junto do ok exige regravar o firmware
desktop/ BalancaClient.java Consome o fluxo SSE do backend, com reconexão automática ~0 ms somados pelo desktop
Por que o desktop fala HTTP aqui, se a decisão D1-A diz JDBC direto? Porque o peso instantâneo não existe no banco: ele vive na memória do backend e é descartado a cada nova leitura. Não é dado persistido, é sinal de sensor. Todo o acesso a dados do sistema — insumos, movimentações, usuários — continua sendo feito pelo próprio Java via JDBC. Esta é a única porta HTTP da aplicação, e ela existe para um valor que o MySQL nunca vai ter.

A transação que protege o estoque

Registrar uma compra são duas escritas: gravar a movimentação e alterar o saldo do insumo. Se a segunda falhasse depois da primeira, o estoque passaria a mentir. As duas acontecem dentro de uma transação.

O SELECT ... FOR UPDATE trava a linha do insumo até o fim da transação, o que impede duas máquinas da rede local de lerem o mesmo saldo ao mesmo tempo e gravarem valores conflitantes. É a razão técnica pela qual as tabelas usam InnoDB: o outro motor do MySQL não faz transação nem chave estrangeira.

Apêndice

Como abrir o projeto no Eclipse

Passo a passo para quem vai clonar o repositório e rodar o app desktop pela primeira vez. São nove passos; os quatro primeiros são de ambiente e só se faz uma vez.

Antes de tudo, uma armadilha conhecida: uma versão antiga do Eclipse não abre este projeto. Se o import não listar nada, quase sempre é isso — o Kepler (2013), por exemplo, foi feito para Java 7 e não entende record, text blocks nem o pom.xml moderno. É preciso o Eclipse 2024-03 ou mais novo; o testado aqui foi o 2026-06.
  1. Confirmar o JDK 21 ou superior No terminal, java -version. Se acusar 17 ou menos, baixe um JDK 21+ (Temurin ou Oracle). O projeto compila para Java 21 — versões anteriores não conseguem nem ler o código.
  2. Instalar um Eclipse atual, se ainda não tiver Baixe o pacote Eclipse IDE for Java Developers em eclipse.org. É um .zip: basta extrair, não precisa de instalador nem de permissão de administrador. O pacote já vem com um Java 21 próprio, então ele funciona mesmo que o JDK do sistema seja outro.
  3. Clonar o repositório num caminho curto, sem espaços e fora do OneDrive Por exemplo C:\dev\custo-certo. Espaços no caminho e pastas sincronizadas pelo OneDrive causam falhas difíceis de diagnosticar no Eclipse, que grava metadados o tempo todo.
    git clone https://github.com/Custo-Certo/versao_3semestre.git C:\dev\custo-certo
  4. Abrir o Eclipse num workspace também fora do OneDrive Na primeira tela, escolha algo como C:\dev\workspace. Se o seu workspace atual estiver dentro do OneDrive, troque em File → Switch Workspace → Other.
  5. Importar como projeto Maven File → Import → Maven → Existing Maven Projects. Não use General → Existing Projects into Workspace: aquele assistente procura um arquivo .project, que projetos Maven não têm, e a lista vem vazia.
  6. Apontar para a pasta desktop, não para a raiz Em Root Directory, informe C:\dev\custo-certo\desktop. A raiz do repositório é o projeto Node e não tem pom.xml. Deve aparecer uma linha assim na lista:
O que a janela de import deve mostrar
Projects:
  [x] /pom.xml   br.com.custocerto:custo-certo-desktop:1.0.0:jar
  1. Esperar o m2e baixar as dependências Na primeira importação o Eclipse resolve o JavaFX e o driver JDBC do MySQL sozinho. Leva um ou dois minutos e aparece uma barra de progresso no canto inferior direito. Ninguém precisa baixar SDK do JavaFX à mão.
  2. Criar o config.properties e preparar o banco Copie config.properties.example para config.properties dentro de desktop/ e preencha os dados do seu MySQL. Depois rode os dois scripts de src/main/resources/sql/, na ordem. O config.properties não vai para o Git — cada pessoa tem o seu.
  3. Executar pela classe Launcher Botão direito em Launcher.java → Run As → Java Application. Não use a classe App — ver a explicação na tabela abaixo. Com o MySQL ligado, a tela de login abre.

Se algo der errado

O que aconteceCausaSolução
A lista de import fica vazia Eclipse antigo demais, ou assistente errado Use um Eclipse 2024-03+ e o caminho Maven → Existing Maven Projects. Confirme que apontou para a pasta desktop.
A lista fica vazia mesmo com tudo certo O projeto já está no workspace O m2e esconde o que já foi importado. Confira o Package Explorer; se estiver lá, remova com Delete sem marcar "delete contents on disk" e importe de novo.
JavaFX runtime components are missing Executou a classe App Use a Launcher. A App estende Application, e a JVM recusa iniciar uma classe assim quando o JavaFX está no classpath em vez do module path. A Launcher não estende nada e existe só para contornar isso.
Erros de compilação em record, switch ou blocos de texto JRE do projeto abaixo de 21 Window → Preferences → Java → Installed JREs e selecione um JDK 21+. Depois Project → Clean.
Aviso de banco indisponível ao abrir MySQL desligado ou endereço errado Ligue o servidor e confira db.host, db.usuario e db.senha no config.properties. A janela abre mesmo assim, mas o login não funciona.
Eclipse lento, travando ou com erros estranhos de arquivo Workspace ou projeto dentro do OneDrive Mova os dois para um caminho local curto, como C:\dev. O OneDrive sincroniza os metadados do Eclipse e trava arquivos em uso.
Sem IDE também funciona. Pela linha de comando, dentro de desktop/: mvnw javafx:run abre a aplicação, mvnw javadoc:javadoc gera a documentação e mvnw exec:java -Dexec.mainClass=br.com.custocerto.util.DiagnosticoAmbiente testa o ambiente inteiro. O Maven Wrapper baixa tudo o que precisa — só o JDK precisa estar instalado.
